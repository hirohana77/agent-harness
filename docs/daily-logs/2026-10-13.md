## 一、需求与架构规划

### 1. 背景与痛点分析
在经历了多轨迹集群共识比对引擎（Cluster Consensus Engine）的落地后，`agent-harness` 已经能够从 $N$ 条并行自主 Rollout 中通过多序列比对（MSA）挖掘出规范黄金路径（Canonical Golden Trajectory）与死亡陷阱（Dead-End Traps）。然而，在智能体自主研发闭环与实际业务落地中，依然存在突出的断层：
- **评测产物与执行闭环脱节**：提炼出的黄金轨迹与失败死区目前仅停留在静态评估报告与 JSON/Markdown 摘要中，缺乏将这些离线知识自动化转化为模型可理解、可遵循的“先验行动策略 (Actionable Policy)”的蒸馏机制；
- **重复踏入同一报错陷阱**：在长任务重试或相似任务派发时，智能体缺乏负向禁阻规则（Negative Anti-Patterns）约束，经常因上下文重置而反复执行高危破坏性命令或已证明无效的死循环试探；
- **Prompt Token 预算膨胀**：直接将原始长轨迹作为少样本示例（Few-Shot Exemplar）注入提示词会严重超出上下文窗口限制（Token Bloat），且混杂大量冗余探测与噪音输出，缺乏在保留关键里程碑的前提下进行结构化剪枝与压缩的机制；
- **缺乏运行时动态前向引导**：在智能体执行过程中，缺乏状态机来跟踪其距离目标里程碑的偏移度（Path Divergence），无法在偏航或误入陷阱的第一时间下发动态纠偏 Hint 或即时阻断信号；
- **缺乏与动态断点控制器 (Steering) 的自动化联动**：此前定义的断点与干预规则依赖人工编写，缺乏由黄金轨迹和死亡陷阱自动生成可执行断点蓝图（Steering Blueprints）的桥梁。

### 2. 架构设计与实现方案
围绕 **轨迹策略蒸馏与自愈先验引导引擎 (Trajectory Policy Distillation & Dynamic Guidance Engine)** 进行系统化落地（`src/distillation`）：
- **核心契约与 Schema 规范 (`src/distillation/types.ts`, `src/distillation/schemas.ts`)**：
  - 定义不变里程碑路线图 `MilestoneGuidance`（包含重要级 `critical` / `recommended`、目标工具与参数正则模式）；
  - 定义负向防陷阱规则 `NegativePatternGuidance`（包含严重级 `critical` / `warning`、触发条件、错误关键字与自愈补救提示）；
  - 定义受 Token 预算约束的示范轨迹 `FewShotExemplar` 与轮次结构 `FewShotTurn`；
  - 定义与 `src/steering` 兼容的动态干预蓝图 `SteeringActionBlueprint`；
  - 定义全链路运行时状态 `GuidanceState` 与动态反馈契约 `DynamicGuidanceFeedback`（动作包含 `continue`、`hint`、`warn`、`block`、`milestone_advance`、`diverged`）。
- **策略蒸馏器 (`src/distillation/distiller.ts`)**：
  - 支持多源知识抽取：可从 `ClusterConsensusResult`（瓶颈与陷阱）、`CanonicalTrajectory`（纯黄金轨迹）或单条原始 `Trajectory` 中智能提炼；
  - 自动正向挖掘：基于瓶颈节点的出现频率与成功相关系数 ($r$) 提炼里程碑序列；
  - 自动负向挖掘：将死区陷阱与高频报错聚类为负向防陷阱规则；
  - 冗余步骤压缩与 Token 预算智能裁剪：自动折叠连续相同探测命令，针对目标 Token 预算动态剪除中间非关键探索轮次，并自动压缩长文本输出；
  - 动态断点规则蓝图自动合成：输出与 `SteeringController` 完全兼容的断点规则集。
- **运行时动态引导分发器 (`src/distillation/dispatcher.ts`)**：
  - 内置智能体状态跟踪器，评估每一轮执行上下文（工具名、参数、执行结果与思考内容）；
  - 内置正则与字符串缓存（`PatternRegexCache`），确保高频匹配亚毫秒级响应；
  - 优先进行高危陷阱拦截，触发阻断并提供针对性自愈补救建议；
  - 顺次核验里程碑达成状态，输出进阶反馈；当智能体连续非预期试探超过容忍度时触发偏航警报（`diverged`）。
- **多端格式化与提示词适配器 (`src/distillation/formatters.ts`)**：
  - `formatAsMarkdown`：生成 Markdown 格式的系统提示词补充小节；
  - `formatAsAnthropic`：适配 Claude 的 XML 标签规范；
  - `formatAsOpenAI`：生成符合 OpenAI 函数调用规范的对话消息数组；
  - `formatAsSteeringConfig`：导出断点拦截配置文件。
- **统一门面与报告器 (`src/distillation/engine.ts`, `src/distillation/reporters/*`)**：
  - `PolicyDistillationEngine` 统一对外门面，串联蒸馏、格式化、动态调度与文件导出；
  - 提供 `terminal`（高亮 ANSI 卡片与里程碑矩阵）与 `markdown` 结构化报告器。
- **CLI 命令行扩展 (`agent-harness distill`)**：
  - 新增 `agent-harness distill` 命令，支持 `--input`、`--format`、`--token-budget`、`--target`、`--output`、`--export-steering` 等实用参数。
