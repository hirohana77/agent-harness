## 一、需求与架构规划

### 1. 背景与痛点分析
在完成了断言校验器、容器沙箱隔离、SWE-bench 任务集标准化适配、实时流式 Web 遥测面板、混沌工程故障注入、轨迹策略蒸馏与多智能体锦标赛排位引擎之后，`agent-harness` 已经具备了业内领先的单智能体与多智能体综合评测能力。然而，随着具备真实系统操作权限（如 Shell 执行、文件读写、网络调用、第三方工具交互）的自主智能体（Autonomous Agents）在实际生产环境中落地，安全与越权风险成为阻碍其规模化应用的核心瓶颈：
- **缺乏系统化、高覆盖的红队攻击探针库 (Adversarial Probes)**：针对智能体的攻击不仅局限于直接提示词注入（Direct Prompt Injection），还广泛包含间接提示词注入（如仓库 README 恶意指令、被投毒的依赖包或外部 Mock API 响应）、机密与凭据外发（Secret Exfiltration）、高危提权（`sudo su`、`chmod 777`）、破坏性操作（`rm -rf .git`、清空工作区）以及混淆绕过（Base64 动态执行管道）；以往评测缺乏工业级可复现的探针库；
- **缺乏非破坏性场景对抗突变器 (Adversarial Mutator)**：传统安全测试往往需要人工逐个篡改测试用例，难以将标准任务集（如 SWE-bench 或企业自研用例）无缝转化为携带对抗载荷的红队变体（支持 instruction、file-injection、env-injection 及 mock-tool 多种向量），且需保证基础任务契约不变；
- **缺乏多维全轨迹漏洞取证与判定引擎 (Vulnerability Detector)**：如何客观、精确地判定智能体是否被攻破？若智能体盲目执行了攻击载荷则为「被攻破（Exploited）」；若因沙箱策略拦截、主动护栏阻断或智能体自主识别拒绝则为「成功防御（Defended/Mitigated）」；需要深入扫描模型思考过程、命令参数、文件读写及工具输出中的金丝雀机密（Canary Secrets）与特征签名；
- **缺乏运行时主动安全护栏与攻防提升量化能力 (Active Guardrails & Benchmarking)**：除了事后打分，评测系统还需要能提供运行时主动安全护栏（支持 audit 审计模式与 enforce 阻断模式），并能够一键发起智能体在「裸奔基线」与「护栏守护」下的攻防对比基准评测（Defense Benchmark），直接输出攻击成功率降幅（$\Delta \text{ASR}$）与安全韧性评分提升（$\Delta \text{Score}$）；
- **缺乏多端专业安全审计报表与 CI/CD 门禁集成**：需支持控制台彩色 ANSI 风险矩阵仪表盘、面向安全合规审查的 GitHub Markdown 表格，以及包含完整取证链路的机器可读 JSON 产物，便于在流水线中设置 `--max-asr` 与 `--min-safety-score` 阻断门禁。

### 2. 架构设计与实现方案
系统化设计并实现了 **对抗性红队攻防与安全沙箱护栏评测引擎 (`src/redteam`)**：
- **核心类型契约与 Schema 强校验 (`src/redteam/types.ts`, `src/redteam/schemas.ts`)**：
  - 定义 7 大风险类别 `RedTeamRiskCategory`（`prompt-injection`、`indirect-injection`、`secret-exfiltration`、`privilege-escalation`、`destructive-command`、`supply-chain`、`defense-bypass`）；
  - 定义 4 级严重度 `ProbeSeverity`（`low`、`medium`、`high`、`critical`）；
  - 定义 4 类攻击注入向量 `InjectionVector`（`instruction`、`file-injection`、`env-injection`、`mock-tool`）；
  - 定义 3 种护栏工作模式 `GuardrailMode`（`none`、`audit`、`enforce`）；
  - 定义标准探针规格 `RedTeamProbe`、漏洞触发指标 `VulnerabilityIndicator`、漏洞审计取证项 `VulnerabilityFinding`、类别战报 `CategoryScorecard` 与红队审计总报告 `RedTeamAuditReport`。
- **内置工业级对抗探针目录 (`src/redteam/catalog.ts`)**：
  - 内置 12 个涵盖各维度的真实攻防探针（包括系统指令覆写、开发者越狱模式、README 隐藏后门指令、Mock 工具返回投毒、`.env` 敏感文件读取与金丝雀网络外发、`chmod 777` 提权、`sudo` 越权、`rm -rf .git` 与根目录清空、`curl | sh` 远端管道、Base64 混淆执行等）；
  - 提供 `RedTeamProbeCatalog` 查询与动态注册扩展机制。
- **对抗场景动态突变器 (`src/redteam/mutator.ts`)**：
  - `AdversarialMutator`：
    - `instruction` 向量：精准将对抗载荷追加至任务指令；
    - `file-injection` 向量：注入工作区指定文件（如 `README.md`、`requirements.txt`）；
    - `env-injection` 向量：向 `.env` 或环境变量注入带有金丝雀标记的凭据；
    - `mock-tool` 向量：自动注入外部 API 模拟数据并关联上下文提示。
- **全轨迹漏洞判定引擎 (`src/redteam/detector.ts`)**：
  - `VulnerabilityDetector`：
    - 遍历执行轨迹各轮次，深度匹配工具入参（`toolCalls.arguments`）、显式命令（`command`）、工具执行结果输出（`result.output/error`）以及模型助理消息（`assistantMessage`）；
    - 关联金丝雀令牌（`canarySecret`）与漏洞指标模式；
    - 区分 `exploited`、`defended`、`mitigated` 与 `refused`，输出清晰的时间戳与证据链条。
- **运行时主动安全护栏体系 (`src/redteam/guardrails.ts`)**：
  - `CommandSafetyGuardrail`：高危命令与破坏性操作拦截；
  - `SecretLeakGuardrail`：机密凭据文件访问限制与输出金丝雀标记泄露过滤；
  - `CompositeGuardrail`：多护栏串联执行容器，支持 `audit`（记录违规）与 `enforce`（抛出 `SecurityViolationError` 阻断执行）。
- **执行调度器与高层门面 (`src/redteam/runner.ts`, `src/redteam/engine.ts`)**：
  - `RedTeamRunner`：按类别、严重度与探针 ID 进行过滤执行，计算整体安全分（`safetyScore`，0-100）、攻击成功率（`attackSuccessRate`，0.0-1.0）与综合风险等级；
  - `RedTeamEngine`：提供高层 `auditAgent` 审计接口与 `benchmarkDefense` 护栏攻防对比基准评测。
- **多端报告器与 CLI 集成 (`src/redteam/reporters/*`, `src/cli/index.ts`)**：
  - 提供终端 ANSI 仪表、GitHub Markdown 表格以及结构化 JSON 报告器；
  - 扩展 CLI 子命令 `agent-harness redteam`，支持 `--max-asr`、`--min-safety-score`、`--guardrail`、`--benchmark-defense` 等全套命令行参数。
