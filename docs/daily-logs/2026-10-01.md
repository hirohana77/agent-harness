## 一、需求与方向规划

### 1. 背景与痛点
此前 `agent-harness` 具备隔离沙箱执行、确定性离线回放以及多维断言验证能力，但执行过程中的轨迹（Trajectory）记录完全依托内存缓冲，仅在场景执行终态统一导出。
在大模型智能体进行耗时较长的多轮次推理（Multi-turn Reasoning）、复杂 Shell 编译测试或频繁工具交互场景下，存在以下缺陷：
- 缺乏实时执行可见性，终端用户与 CLI 无法直观感知当前处于哪一轮次、正在执行何种工具；
- 缺乏实时流式持久化机制，若宿主机器中断或进程异常终止，之前的轮次与耗时数据将完全丢失；
- 外部集成（如 Web 控制台、SSE 服务、自动化评测监控大盘）难以实时挂载监听与预警。

### 2. 架构设计与模块规划
围绕**实时流式 Trajectory 事件总线与遥测管道**进行深度增强：
- **`src/events/types.ts`**：
  - 定义统一的 `TrajectoryEvent` 判别联合类型（`scenario:start`, `scenario:complete`, `turn:start`, `turn:complete`, `tool:start`, `tool:end`, `budget:warning`, `status:change`, `error`, `custom`）。
  - 定义事件监听器契约与 `TrajectoryStreamObserver` 流式观测器接口。
- **`src/events/bus.ts`**：
  - 构建高性能发布-订阅总线 `TrajectoryEventBus`，支持精确类型匹配、前缀通配符（如 `tool:*`, `turn:*`）以及全局通配符 `*`。
  - 基于模式分组索引（Exact Map / Prefix Map / Global Set）优化派发性能，规避全局 O(N) 扫描。
  - 实现同步 `emit` 与并发异步 `emitAsync`（`Promise.allSettled`），支持 `waitForEvent` 异步条件等待与超时保护。
  - 具备零崩溃异常边界隔离机制，单个监听器异常不会影响场景正常执行。
- **`src/events/observers/`**：
  - `LiveConsoleObserver`：终端高亮彩色进度流，输出轮次、工具调用状态、耗时与 Token 统计。
  - `JsonLinesStreamObserver`：支持将事件实时流式追加写入 NDJSON（JSON Lines）文件，保障断电不丢数据。
  - `BufferedStreamObserver`：带容量上限约束的滑动窗口事件缓冲，支持事件过滤、排空（drain）与总线重放（replay）。
- **`src/core/harness.ts` & `src/trajectory/recorder.ts` & `src/mock/dispatcher.ts`**：
  - `AgentHarness.runScenario` 原生注入 `eventBus` 与 `observers` 配置。
  - `TrajectoryRecorder` 在轮次启动、工具调用、轮次完成及终态更新时自动派发事件，并在 Token/Turn 消耗达 80% 时自动发射预警。
  - `VirtualToolDispatcher` 与工具调用生命周期统一联动，串联 `tool:start` 与 `tool:end`。
- **`src/cli/index.ts`**：
  - 为 `run` 命令新增 `--live`（终端实时流）与 `--stream-jsonl <path>`（NDJSON 文件持久化）参数。
