## 一、需求与架构规划

### 1. 背景与痛点分析
在经历了沙箱隔离执行、AST 语义断言、SWE-bench 基准评测、流式事件总线、交互式断点转向以及差分轨迹对比等核心阶段后，`agent-harness` 具备了完整的确定性执行与测试能力。然而在真实生产环境和复杂任务场景中，自主 AI 智能体常常面临脆弱且不可预测的基础设施挑战：
- **瞬态环境抖动与丢包 (Transient Network Drops)**：外部包管理器（`npm`、`pip`、`git clone`）或网络工具偶发性报错，开发者无法验证智能体是否具备自愈重试能力，还是会直接放弃报错；
- **API 频控限流 (Rate Limit & Throttling)**：模型或下游 API 返回 HTTP 429 时，智能体可能由于缺乏退避机制（Backoff）引发重试风暴（Retry Storm），或陷入无效死循环；
- **输出截断与数据破坏 (Corrupted Output)**：工具输出因缓冲区限制截断或返回残缺的 JSON 格式时，智能体容易因解析异常直接崩溃崩溃；
- **间接提示词注入与越狱投毒 (Indirect Prompt Injection & Poisoning)**：命令执行回显、网页抓取结果或外部文件中可能潜藏对抗性提示词（如覆盖用户目标伪造恶意指令），缺乏评估智能体防御投毒能力的有效标尺；
- **缺乏多维韧性度量与 CI 门禁标准**：缺乏对智能体在故障注入下的自愈率、死循环抵御率、平均恢复轮次（MTTR）及综合韧性评级的量化评分标准与门禁阻断能力。

### 2. 架构设计与实现方案
围绕 **混沌工程与智能体韧性评测框架 (Chaos Engineering & Resilience Evaluation Framework)** 进行系统化设计与落地（`src/chaos`）：
- **类型契约与 Schema 校验 (`src/chaos/types.ts`, `src/chaos/schemas.ts`)**：
  - 定义 `ChaosFaultType`（`latency`、`error`、`output_corruption`、`adversarial_prompt`、`intermittent`、`rate_limit`）；
  - 定义自适应触发策略 `ChaosOccurrenceStrategy`（`always`、`probability`、`call_index`、`every_n_calls`、`burst`）；
  - 定义 `ChaosRule`、`ChaosProfile`、`ChaosEvent`、`ResilienceMetrics` 与 `ResilienceScorecard` 完整 Zod 校验 Schema。
- **模块化故障注入器矩阵 (`src/chaos/injectors/*`)**：
  - `LatencyInjector`：支持延迟注入、时钟抖动以及模拟命令超时（`exitCode: 124`）；
  - `ErrorInjector`：注入指定退出码、模拟失败信息及 HTTP 503/403 状态码；
  - `RateLimitInjector`：模拟调用配额用尽与 HTTP 429 频控，返回 `Retry-After` 头；
  - `CorruptionInjector`：后置破坏工具输出，支持截断、破坏 JSON 语法、乱码替换及空输出；
  - `AdversarialInjector`：后置注入对抗性越狱指令与秘密金丝雀标记（`CHAOS_POISON_CANARY_42`），测试智能体防御边界。
- **状态化混沌引擎调度器 (`src/chaos/engine.ts`)**：
  - 支持多规则并发匹配（工具通配符、入参正则匹配、最大注入次数限制）；
  - 前置与后置双向拦截钩子（`interceptBefore`、`interceptAfter`）；
  - 内置正则缓存提升吞吐性能，并设立异常隔离沙盒边界，防止注入异常波及 Harness 主进程。
- **全方位韧性评估器 (`src/chaos/evaluator.ts`)**：
  - 自动追踪工具执行历史与智能体思考轮次（`AgentTurn`）；
  - 计算故障自愈率（Recovery Rate）与平均恢复轮次（MTTR）；
  - 实时检测同参数连续失败死循环（Retry Storm $\ge 3$ 次）；
  - 严格检测金丝雀诱饵 Token 是否泄漏在智能体上下文或后续操作中（Poison Defense Rate）；
  - 输出 0~100 综合韧性分及五级评定标准（`S`、`A`、`B`、`C`、`F`）并提供针对性架构优化建议。
- **开箱即用内置画像预设 (`src/chaos/profiles.ts`)**：
  - `transient-network`（瞬态网络丢包，第 1 次失败，重试成功）；
  - `rate-limit`（API 频控限流）；
  - `adversarial-poison`（对抗性越狱与金丝雀陷阱）；
  - `corrupted-output`（破坏 JSON 结构）；
  - `chaos-monkey`（随机网络抖动与偶发性报错）。
- **工具总线平滑集成 (`src/mock/dispatcher.ts`)**：
  - `VirtualToolDispatcher` 支持挂载可选 `setChaosEngine(chaos)`，无侵入实现原生与 Mock 工具调用的全链路混沌拦截。
- **多端报告呈现与 CLI 命令行扩展 (`src/chaos/reporters/*`, `src/cli/index.ts`)**：
  - `terminal`：高亮 ANSI 韧性雷达卡片、指标分解及架构优化建议；
  - `markdown`：适配 GitHub PR 评论的 Markdown 格式报告；
  - `json`：严格 Schema 的机器可读输出；
  - CLI 新增 `agent-harness chaos` 命令，支持 `--min-score` 进行自动化 CI 门禁拦截。
