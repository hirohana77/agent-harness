## 一、需求与架构规划

### 1. 背景与痛点分析
在完成了 AST 语义断言、多容器后端隔离、SWE-bench 评测适配器、实时遥测仪表盘、混沌工程故障注入、轨迹策略蒸馏、竞技场排位算法、红队对抗安全护栏以及认知病理自愈诊断（Reflexion）等模块之后，`agent-harness` 已经具备了业内完备的评测闭环。然而，在复杂长链路任务（例如软件工程修复任务、多工具系统运维编排，通常持续 30-100 个执行轮次）中，开发者与评测工程师面临着严峻的调试与归因痛点：
- **缺乏逐轮次沙箱环境快照与回滚能力**：传统的执行重放（Replay）只能从头到尾单向正向执行。当智能体在第 38 轮触发致命故障时，开发者无法在不重跑前 37 轮的情况下直接查看第 37 轮的文件系统、环境变量和累积差异（Delta Diffs），更无法实现任意轮次的状态时间旅行跳转；
- **缺乏自动化根因二分搜索定位能力（Trajectory Bisect）**：在长轨迹中，故障往往在早期某一轮次（如误改配置、引入语法错误）埋下伏笔，但在数十轮之后才在测试中爆发。传统排查需要人工逐轮肉眼比对或遍历验证。缺乏类似软件工程中 `git bisect` 的自动化二分检索算法，无法在 $O(\log N)$ 步数内精准锁定第一个破坏不变量或引入退化的轮次与责任工具调用；
- **缺乏细粒度条件断点与工作区观察点（Breakpoints & Watchpoints）**：智能体执行具有随机性与非确定性。开发者需要能够在特定条件满足时（如工具非零退出码、特定异常正则匹配、某核心代码文件被修改）自动挂起步进并打印上下文，当前业界评测套件普遍缺乏该机制；
- **缺乏反事实分支推演与“What-If”假设检验能力（Counterfactual Exploration）**：对于智能体决策质量的评估，最重要的命题之一是“如果第 $K$ 步工具返回了正确结果，后续任务是否能够顺利恢复完成？”缺乏在历史任意时间节点分叉（Fork）、注入合成变异（覆盖工具返回值、修补工作区代码、注入反事实提示词）并向后模拟推演的能力，无法量化智能体决策树的脆弱点与拯救窗口；
- **缺乏工程化集成报表与 CI/CD 质量门禁**：缺乏针对时间旅行回溯与二分归因的可视化终端时间轴、GitHub Markdown 报告与结构化 JSON 产物，难以在自动化流水线中对退化轮次设置 `--fail-on-regression` 质量拦截。

### 2. 架构设计与实现方案
系统化设计并实现了 **智能体时间旅行调试与反事实执行引擎 (`src/timetravel`)**：
- **核心类型契约与 Schema 强类型校验 (`src/timetravel/types.ts`, `src/timetravel/schemas.ts`)**：
  - 定义虚拟文件系统规格 `VirtualFile` 与工作区状态契约 `VirtualFSState`；
  - 定义 4 类文件差异模式 `FileDeltaType`（`created`、`modified`、`deleted`、`unchanged`）与 `FileDelta`；
  - 定义状态快照 `TurnSnapshot`（涵盖 `turnNumber`、`virtualFs`、`env`、`toolCalls`、`fileDeltas`、`cumulativeTokens` 与时长）；
  - 定义 6 类断点条件 `BreakpointConditionType`（`turn`、`tool`、`exit-code`、`error-pattern`、`file-changed`、`custom`）与断点契约 `Breakpoint`；
  - 定义文件观察点契约 `Watchpoint` 与触发模式（`create`、`modify`、`delete`、`any`）；
  - 定义自动化二分搜索规范：`BuiltinPredicateType`、`BisectEvaluationStep` 与 `BisectResult`；
  - 定义 5 类反事实变异模式 `MutationType`（`override-tool-result`、`patch-file`、`delete-file`、`inject-prompt`、`modify-arguments`）；
  - 定义分支结局差异矩阵 `BranchOutcomeDelta`（状态跃迁 `rescued` / `worsened` / `neutral` / `identical`、轮次增减与 Token 开销差）与 `CounterfactualBranch`；
  - 定义多端综合报表契约 `TimeTravelReport`。
- **逐轮次工作区快照管理器 (`src/timetravel/snapshot.ts`)**：
  - `SnapshotManager`：基于 SHA-256 增量哈希计算，自动解析工具调用（`file_write`、`delete_file`、`patch_file` 以及 Shell 重定向 `echo >`、`echo >>`、`export` 与 `rm`），构建全轨迹虚拟文件系统演进视图；
  - 提供 `restoreTurn(turnNumber)` 瞬时深拷贝恢复状态与 `diffTurns(turnA, turnB)` 任意跨度差异比对；
  - 支持写时复制与快照缓存容量限制（`maxCachedSnapshots`），兼顾性能与内存安全。
- **时间旅行轨迹步进控制器 (`src/timetravel/stepper.ts`)**：
  - `TimeTravelStepper`：维护当前游标位置，支持 `stepForward()`、`stepBackward()`、`jumpToTurn()` 与 `reset()`；
  - 管理动态条件断点与文件观察点集合，并在每次步进时实时求值；
  - `runUntilBreakpoint()`：连续执行并自动暂停于下一个命中断点或观察点，返回完整步进结果 `StepResult`。
- **自动化缺陷二分搜索定位器 (`src/timetravel/bisect.ts`)**：
  - `TrajectoryBisector`：以 $O(\log N)$ 复杂度在轨迹轮次序列中执行二分搜索，精准锁定引入缺陷的第一个轮次（`firstFaultyTurn`）；
  - 开箱即用支持 4 种内置不变量断言（`exit-code-success`、`file-exists`、`file-contains`、`no-error-output`）及自定义同步/异步断言 Oracle；
  - 自动提取责任工具调用、输出根因摘要（Root Cause Description）与置信度评分（Confidence Score）。
- **反事实分支推演与变异引擎 (`src/timetravel/counterfactual.ts`)**：
  - `CounterfactualEngine`：在指定轮次 $T_k$ 分叉并应用合成变异；
  - 向后推演重放并量化分支结局状态跃迁、轮次节省（Turn Reduction）与 Token 经济学开销对比，构建 `CounterfactualBranch`。
- **高层门面调度器 (`src/timetravel/engine.ts`)**：
  - `TimeTravelEngine`：提供高层 `createSession` 交互调试会话、`bisect` 自动二分归因、`forkBranch` 反事实分支推演与 `generateReport` 综合报表生成。
- **多端专业诊断报告器与 CLI 集成 (`src/timetravel/reporters/*`, `src/cli/index.ts`)**：
  - 提供终端 ANSI 视觉时间轴报表、GitHub Markdown 格式化战报以及结构化 JSON 导出；
  - 扩展 CLI 子命令 `agent-harness timetravel`，支持 `-t, --trajectory`、`-b, --bisect`、`--predicate-type`、`--predicate-arg`、`--fork-turn`、`--override-exit-code`、`--override-output`、`--export-snapshots` 与 `--fail-on-regression` 等全套命令行参数。
